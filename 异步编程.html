    9. 异步编程

    上一章介绍了线程：我们可以“同时”执行多段代码，对它们进行同步，并通过执行器（[ExecutorService]）把任务分配给线程池。本章讨论一个相关但不同的问题：如何编写一个需要大量等待（等待磁盘、网络或数据库）的程序，而又不会在这些等待期间占用线程。

    Java 没有用于此目的的语言关键字（其他语言，如 C# 或 JavaScript，有关键字 [async] 和 [await]）。它提供了两种相互补充的解决方案，本章都会介绍：

    • [CompletableFuture<T>] 类（Java 8，此后有所增强）表示一个正在进行的操作，其后续步骤通过回调方法进行组合：“当结果就绪时，先做这个，再做那个”（[thenApply]、[thenCompose]、[thenCombine]、[allOf]……）。没有线程在等待：由操作的完成触发下一步；
    • 另一方面，虚拟线程（Java 21）允许你编写阻塞式、自上而下阅读的顺序代码：当虚拟线程等待输入/输出时，JVM 会把它从执行它的系统线程（其“载体线程”）上分离，并释放该线程供另一个虚拟线程使用。这使得只需几个系统线程就可以拥有数十万个虚拟线程。这是 Java 针对其他语言用 [async] / [await] 来解决的问题所给出的现代方案。

    这些工具如今无处不在：后续章节将用它们来访问数据库、编写通过虚拟线程为每个客户端提供服务的 TCP 服务器、使用 [java.net.http.HttpClient] 的 Web 客户端，以及使用 Spring Boot 的 Web 服务。

    本章的所有示例都是紧凑源文件（[Async01.java]、[Async02.java]……），在 [09-async] 文件夹中使用 [java AsyncNN.java] 运行。其中许多示例使用 [System.nanoTime()] 测量执行时间：显示的毫秒数在每次运行和每台机器之间都会有所不同（这些示例是在一台双处理器机器上运行的）。重要的是数量级：是 1 秒还是 10 秒，是 300 毫秒还是 0 毫秒。

    9.1. 为什么需要异步

    9.1.1. 会等待的操作

    程序执行两类工作：

    • 计算任务，占用处理器：对列表排序、计算税款、分析文本；
    • 输入/输出 （I/O），本质上就是等待外围设备：从磁盘读取文件、向 Web 服务器发送请求并等待其响应、在数据库服务器上执行 SQL 查询。

    它们的数量级差别很大。处理器每秒执行几十亿条指令。磁盘（SSD）上的一次读操作大约需要十分之一毫秒；一次局域网往返只需不到一毫秒；到位于国家另一端的服务器的一次往返需要几十毫秒；而一个稍微复杂的 SQL 请求有时可能需要几秒。在这些等待期间，处理器本可以执行数百万条指令。

    当程序使用阻塞方法通过网络连接读取一行数据时，执行这次读取的线程会被阻塞：它什么也不做，但仍然存在。“经典”的 Java 线程——现在称为“平台线程”——就是操作系统线程：它占用内存（其栈，大约一兆字节），被系统所识别，而且最重要的是，它无法再去做其他事情。在一次只做一件事的小型控制台程序中，这不是问题。但在两种情况下，问题就严重得多：

    • 在服务器中：每个由被阻塞线程服务的客户端都会占用一个线程。如果服务器的线程池有 N 个线程，而这 N 个线程都在执行阻塞操作，就没有空闲线程可供新客户端使用。现代服务器可以处理数千个同时到来的请求：之所以能做到，是因为它的等待操作不会占用系统线程；
    • 在图形用户界面中：由单个线程（UI 线程，即 Swing 的“事件分派线程”、“JavaFX 应用程序线程”）处理点击和窗口重绘。如果它被下载操作阻塞，窗口就会冻结。

    异步的做法是发起 I/O 操作，在其进行期间释放系统线程（硬件和操作系统传输数据并不需要它），然后在操作完成后恢复工作，可能是在另一个系统线程上：

    • 在 [1] 中，平台线程 T1 发起 I/O，并一直阻塞到它结束；
    • 在 [2] 中，虚拟线程 V1 发起 I/O；JVM 把它从其载体线程 P1 上分离，P1 随即可以立即执行其他虚拟线程。当 I/O 完成时，JVM 把 V1 重新挂载到一个空闲的载体线程 P2（也可能就是 P1）上，V1 在阻塞指令之后立即继续执行，就好像什么都没发生过一样。

    程序 [Async01.java] 测量了 100 个操作的差异，每个操作等待一秒（等待用来模拟 I/O）。它使用了我们将在本章后面解释的指令（[Executors.newVirtualThreadPerTaskExecutor]、[CompletableFuture]）：在这里，我们主要关心的是结果。

    // 为什么要异步：100 个操作，每个都等待一秒
// （等待模拟 I/O：磁盘读取、网络请求、SQL 查询……）
import java.lang.management.ManagementFactory;

final int nbOperations = 100;
long start;

void main() throws InterruptedException {
    IO.println(nbOperations + " operations of one second, "
            + Runtime.getRuntime().availableProcessors() + " processors");

    // 1 - 每个操作一个平台线程，每个线程在等待期间被阻塞
    start = System.nanoTime();
    List<Thread> threads = new ArrayList<>();
    for (int i = 0; i < nbOperations; i++) {
        threads.add(Thread.ofPlatform().start(() -> waitFor(1000)));
    }
    display("1 - one platform thread per operation", jvmThreads());
    for (Thread thread : threads) {
        thread.join();
    }
    display("    end", -1);

    // 2 - 操作交给一个 10 个线程的线程池，但它们会阻塞线程池
    start = System.nanoTime();
    try (ExecutorService pool = Executors.newFixedThreadPool(10)) {
        for (int i = 0; i < nbOperations; i++) {
            pool.submit(() -> waitFor(1000));
        }
        display("2 - pool of 10 threads, blocking waits", jvmThreads());
    } // close() 等待所有操作结束
    display("    end", -1);

    // 3 - 每个操作一个虚拟线程：它在等待期间释放其载体线程
    start = System.nanoTime();
    try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
        for (int i = 0; i < nbOperations; i++) {
            executor.submit(() -> waitFor(1000));
        }
        display("3 - one virtual thread per operation", jvmThreads());
    }
    display("    end", -1);

    // 4 - 异步等待：没有线程在等待，由定时器完成每个操作
    start = System.nanoTime();
    var operations = new CompletableFuture<?>[nbOperations];
    for (int i = 0; i < nbOperations; i++) {
        operations[i] = new CompletableFuture<Void>().completeOnTimeout(null, 1000, TimeUnit.MILLISECONDS);
    }
    display("4 - asynchronous waits (CompletableFuture)", jvmThreads());
    CompletableFuture.allOf(operations).join();
    display("    end", -1);
}

// 阻塞等待 [ms] 毫秒
void waitFor(long ms) {
    try {
        Thread.sleep(ms);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}

// 操作启动半秒后 JVM 的平台线程数
int jvmThreads() {
    long elapsed = (System.nanoTime() - start) / 1_000_000;
    if (elapsed < 500) {
        waitFor(500 - elapsed);
    }
    return ManagementFactory.getThreadMXBean().getThreadCount();
}

// 显示耗时，以及（若提供，>= 0）线程数
void display(String message, int nbThreads) {
    String threadsInfo = nbThreads < 0 ? "" : String.format(", %3d threads in the JVM", nbThreads);
    long elapsed = (System.nanoTime() - start) / 1_000_000;
    IO.println(String.format("%-44s : %5d ms%s", message, elapsed, threadsInfo));
}

    说明：

    • 第 12–22 行：最简单的方案——每个操作一个平台线程。[Thread.ofPlatform().start(task)] （Java 21）创建并启动一个线程，就像 [new Thread(task).start()] 一样。每个线程执行 [Thread.sleep(1000)]：它被阻塞一秒钟。这 100 次等待同时发生，整个过程恰好耗时一秒（结果的第 4 行），但代价是多出 100 个系统线程：JVM 共有 106 个（第 3 行）。如果有 10,000 个操作，就需要 10,000 个系统线程；
    • 第 24–32 行：操作被分配给一个 10 线程的线程池（[Executors.newFixedThreadPool(10)]），对计算来说这是一个合理的大小。但这里，这些线程并没有在计算——它们在空闲等待。操作以 10 个为一批等待空闲线程，整个过程耗时……十秒（第 6 行）。这被称为“线程池饥饿”，是把线程池与阻塞式 I/O 混用的服务器中最常见的缺陷。执行器的 [close()] 方法（Java 19）在退出 [try] 时被调用，它拒绝新任务，并等待已提交的任务完成；
    • 第 34–42 行：每个操作一个虚拟线程。[Executors.newVirtualThreadPerTaskExecutor()] （Java 21）返回一个为每个提交的任务创建新虚拟线程的执行器。任务代码与步骤 1 中相同：一个阻塞的 [Thread.sleep(1000)]。然而，被阻塞的虚拟线程不会占用系统线程：JVM 把它从载体线程上分离。这 100 次等待总共持续一秒（第 8 行），而 JVM 只统计到 10 个系统线程（第 7 行）：它自己的服务线程，以及执行这 100 个虚拟线程的两个载体线程——每个处理器一个。虚拟线程不计入这个数目：它们是 JVM 的对象，而不是系统线程；
    • 第 44–52 行：同样的等待，但没有线程在等待。[new CompletableFuture<Void>()] 创建一个“待定”的操作，而 [completeOnTimeout(value, timeout, unit)] （Java 9）要求在超时到期时用指定的值完成它。由 JVM 的单个定时器管理这 100 个超时。[CompletableFuture.allOf(...)] 返回一个在所有其他操作完成时完成的操作，而 [join()] 等待它结束。整个过程持续一秒（第 10 行），与步骤 3 相比只多了一个线程——定时器线程（第 9 行）；
    • 第 55–62 行：[Thread.sleep] 如果线程在休眠期间被中断，可能抛出受检异常 [InterruptedException] （我们将在取消一节中进一步讨论）；[waitFor] 方法拦截了它，这样第 16、28 和 38 行的 lambda 就不必处理它；
    • 第 64–71 行：[ManagementFactory.getThreadMXBean().getThreadCount()] 返回 JVM 的存活平台线程数。[ManagementFactory] 类属于模块 [java.management]：紧凑源文件只会自动导入模块 [java.base]，因此才有第 3 行的导入。

    让我们记住这个教训：要等待，就不能阻塞任何系统线程。异步并不会让 I/O 变得更快；它让你可以用很少的系统线程同时处理大量 I/O 操作，同时保持应用程序所需的线程可用。Java 为此提供了两种方法：创建 [CompletableFuture] （步骤 4），或者编写由虚拟线程执行的普通阻塞代码（步骤 3）。

    9.1.2. 几种先后出现的模型

    Java 提供过几种编写等待而不阻塞的代码的方式。较早的方式仍然出现在现有代码中，因此认识它们是有益的。

    模式
    引入版本
    原理
    [Future] 与运行时
    Java 5（2004）
    [ExecutorService.submit] 把任务分配给线程池，并返回一个 [Future<T>]，它代表即将得到的结果。但获得该结果的唯一方式是通过 [get()] 阻塞等待。
    NIO.2 的回调方法
    Java 7（2011）
    异步通道 （[AsynchronousSocketChannel]、[AsynchronousFileChannel]）发起一个操作并接收一个回调对象（[CompletionHandler]），操作完成后，由线程池中的线程调用其方法 [completed] 或 [failed]。
    [CompletableFuture]
    Java 8（2014）
    一种你可以自行终结的 [Future] ，其执行序列由回调方法（[thenApply]、[thenCompose]、[exceptionally]……）组合而成；响应式流 [java.util.concurrent.Flow] （Java 9）是它针对值序列的扩展。响应式库（Spring WebFlux 使用的 Project Reactor、RxJava）基于相同的概念。
    虚拟线程
    Java 21（2023）
    普通的阻塞代码，由虚拟线程执行：JVM 在等待期间释放系统线程。这是当今新应用程序推荐使用的模型。
    结构化并发
    Java 21 至 Java 25 的预览特性
    [StructuredTaskScope] 把一组由虚拟线程执行的子任务组织成单个代码块，具有共享的错误处理和取消机制（见本章末尾）。

    回调方法有一个缺点：代码是碎片化的。自然读作“连接，然后读取，然后显示”的逻辑，变成了一个发起连接的方法、一个发起读取操作的回调方法，以及另一个显示结果的回调方法；变量必须在这些方法之间共享，异常在不同的位置被捕获，而一个简单的循环（“只要还有数据就读取”）则变成一个递归调用自身的回调方法。[CompletableFuture] 通过把各步骤链接起来，让这种碎片化更易读；虚拟线程则让它消失：异步代码采用同步代码的形式，因为它就是同步代码。

    程序 [Async02.java] 用两种极端的方式实现同一个 TCP 客户端：首先使用 NIO.2 的回调方法，然后使用由虚拟线程执行的阻塞代码。它还包含一个由线程运行的小型服务器，用来响应两个客户端（网络编程将在第 12 章详细介绍；目前只需知道客户端连接到服务器并读取服务器发送给它的消息即可）。

    // 同一个 TCP 客户端，先用回调方法编写（NIO.2，Java 7），再用虚拟线程编写（Java 21）
final int port = 27500;
final InetAddress local = InetAddress.getLoopbackAddress();
final ByteBuffer buffer = ByteBuffer.allocate(1024);
final CountDownLatch end = new CountDownLatch(1);

void main() throws IOException, InterruptedException {
    // 一个由线程执行的最小服务器：它为两个客户端提供服务，然后停止
    var listener = new ServerSocket(port, 10, local);
    Thread server = Thread.ofPlatform().name("server").start(() -> {
        try (listener) {
            for (int i = 1; i <= 2; i++) {
                try (Socket service = listener.accept()) {
                    // 服务器需要一些时间才回答
                    Thread.sleep(500);
                    byte[] message = ("Hello client no. " + i).getBytes(StandardCharsets.UTF_8);
                    service.getOutputStream().write(message);
                }
            }
        } catch (IOException | InterruptedException e) {
            display("server: " + e);
        }
    });
    display("start of the program");

    // 1 - “回调方法”风格：AsynchronousSocketChannel 和 CompletionHandler
    var client = AsynchronousSocketChannel.open();
    // 我们发起连接，并提供完成后要回调的对象
    client.connect(new InetSocketAddress(local, port), client, new Connected());
    display("callbacks: connection started, the program continues");
    // 主线程已无事可做：它等待最后一个回调方法的信号
    end.await();

    // 2 - 阻塞风格，由虚拟线程执行：代码自上而下阅读
    Thread virtual = Thread.ofVirtual().start(() -> {
        try (var client2 = new Socket(local, port)) {
            display("virtual thread: connected, read started");
            byte[] bytes = new byte[1024];
            int nbBytes = client2.getInputStream().read(bytes);
            String message = new String(bytes, 0, nbBytes, StandardCharsets.UTF_8);
            display("virtual thread: received [" + message + "]");
        } catch (IOException e) {
            display("virtual thread: " + e);
        }
    });
    virtual.join();
    server.join();
}

// 第 1 号回调方法：连接已建立（或已失败）
class Connected implements CompletionHandler<Void, AsynchronousSocketChannel> {
    @Override
    public void completed(Void nothing, AsynchronousSocketChannel channel) {
        display("callbacks: connected, read started");
        // 我们用另一个回调对象开始读取服务器的回答
        channel.read(buffer, channel, new Received());
    }

    @Override
    public void failed(Throwable e, AsynchronousSocketChannel channel) {
        display("callbacks: connection failed: " + e);
        end.countDown();
    }
}

    9.2. 未来的任务：Future 和 CompletableFuture

    [Future<T>] （[java.util.concurrent] 包的接口，Java 5）是一个对象，表示一个正在进行或已完成的操作的结果，其类型为 [T]。我们在上一章遇到过它：执行器的 [submit] 方法返回的就是它。你可以查询它（是否已完成？是否成功？）、取消它（[cancel]）、等待它的结果（[get]），但仅此而已：使用结果的唯一方式是阻塞一个线程，直到结果可用。

    [CompletableFuture<T>] 类（Java 8）实现了 [Future<T>] 并增加了两项关键能力：

    • 你可以自行终结它，给出一个结果（[complete]）或一个异常（[completeExceptionally]）；
    • 你可以为它附加一个后续操作——一个在结果可用时执行的函数（[thenApply]、[thenAccept]、[thenCompose]……），它会产生一个新的 [CompletableFuture]。这样，无需任何线程等待，就可以构造出操作链。这些方法由 [CompletionStage<T>] 接口声明，[CompletableFuture] 同样实现了该接口。

    [CompletableFuture] 不是线程。它可能代表由执行器的线程执行的过程（如由 [supplyAsync] 创建的那些），但许多并不由任何线程执行：[Async01.java] 步骤 4 中的那个只是在一秒后由定时器“完成”，而 [HttpClient.sendAsync] 返回的那个则在服务器的响应到达时完成。它是对结果的一个承诺。

    9.3. 异步方法

    9.3.1. 第一种方法：返回 CompletableFuture

    在 Java 中，异步方法就是一个发起操作并立即返回（不等待）一个表示该操作的 [CompletableFuture] 的方法：

    • 如果操作不返回结果，则返回 [CompletableFuture<Void>]；
    • 如果操作返回类型为 [T] 的结果，则返回 [CompletableFuture<T>]。

    9.3.3. JVM 做了什么

    虚拟线程如何能在循环中途被中断、释放其宿主线程，随后又在同一位置恢复执行，并保持相同的局部变量值，甚至可能是在另一个宿主线程上？虚拟线程是一个 Java 对象（[java.lang.VirtualThread]，派生自 [Thread] 的类），它拥有自己的调用栈。为了执行它，JVM 把它“挂载”到一个载体线程上——这是专为此目的保留的 [ForkJoinPool] 中的平台线程，默认情况下该线程池的线程数与处理器数相同。当虚拟线程调用阻塞操作时（[Thread.sleep]，从套接字读取；[BlockingQueue.take]，等待锁……），JVM 中的相关类（在 Java 21 中为此而重写）不会阻塞所在的线程：

    • 它们向系统注册该操作（延迟使用定时器，套接字使用系统的 I/O 通知机制——在 Linux 上是 [epoll] ）；
    • 它们“卸载”虚拟线程：其调用栈帧被复制到堆上，成为一个称为延续（continuation）的对象，而载体线程被归还给 [ForkJoinPool]，由它为该线程分配另一个就绪的虚拟线程；
    • 当操作完成时，虚拟线程再次就绪：它将被重新挂载到第一个可用的载体线程上，其栈帧被重新复制，并在阻塞调用之后立即恢复执行。

    这正是回调方法（“操作完成时回调我”）背后的原理，但分解执行、保存变量以及在调用栈层面恢复上下文的是 JVM，源代码中看不到任何痕迹。其他语言把这项任务交给编译器，由编译器把每个 [async] 方法转换成一个“状态机”；Java 则把它交给 JVM，这使得它能够以同样的方式处理所有现有代码。

    有两个局限需要注意：

    • 某些操作无法使虚拟线程分离；它因此仍然“固定”在其宿主线程上，该宿主线程在等待期间被阻塞。这种情况发生在执行本地方法期间，以及大多数文件读写期间（系统没有提供可供 JVM 使用的文件通知机制）；对于后者，[ForkJoinPool] 会通过临时创建一个额外的载体线程来进行补偿。直到 Java 23，在 [synchronized] 块内等待的虚拟线程也是如此；从 Java 24 起，情况不再如此；
    • 虚拟线程不会加快计算：执行计算的虚拟线程在整个计算期间都占用其宿主线程。虚拟线程适用于大量等待的程序，而不是大量计算的程序（对于后者，可以使用上一章的线程池和并行流）。

    9.6. 取消与截止时间

    9.6.1. Future.cancel 与线程终止

    长时间运行的操作必须能够被取消：用户点击了 [Cancel]、服务器客户端断开了连接、应用程序关闭了，或者发生了超时。Java 为此使用一种协作式机制——线程中断：

    • 线程的 [interrupt()] 方法会设置其中断标志；它并不会停止线程（强制停止的 [Thread.stop] 方法自 Java 20 起已被弃用：它会抛出 [UnsupportedOperationException]）；
    • 如果线程阻塞在可中断的等待中（[Thread.sleep]、[Object.wait]、[Thread.join]、[BlockingQueue.take]、[Future.get]……），等待会被立即中断，并触发 [InterruptedException]，同时清除该标志；
    • 执行计算的线程会使用 [Thread.currentThread().isInterrupted()] 定期检查自己的标志，如果已设置，就优雅地终止；
    • 由执行器返回的 [cancel(true)] 方法，作用于 [Future] 时，会把任务转入 [CANCELLED] 状态，并中断执行它的线程（[cancel(false)] 只是在任务尚未开始时阻止其启动）。取消之后，[get()] 会抛出 [CancellationException]。

    这种机制是协作式的：没有人强行停止一个操作；操作会在能够干净地停止的时刻自行停止。这就是为什么拦截 [InterruptedException] 的方法不得忽略它：它必须要么将其传播出去，要么自行终止，或者至少用 [Thread.currentThread().interrupt()] 重置标志，以便调用代码知道已经请求了中断（我们的 [sleep] 方法就是这样做的）。

// 一个限时 [timeout] 毫秒的处理，调用者也可以停止它
CompletableFuture<Void> processWithTimeout(String name, int duration, int timeout, CompletableFuture<Void> stop) {
    CompletableFuture<String> answer = query(name, duration).orTimeout(timeout, TimeUnit.MILLISECONDS);
    // 全局停止会取消对回答的等待
    stop.thenRun(() -> answer.cancel(false));
    // 我们检查等待是如何结束的
    return answer.handle((text, e) -> switch (e) {
        case null -> text;
        case TimeoutException _ -> name + " : timeout of " + timeout + " ms exceeded";
        case CancellationException _ -> name + " : stopped at the caller's request";
        default -> name + " : " + e;
    }).thenAccept(message -> display("4 - " + message));
}

// 用 AsynchronousFileChannel 读取整个（小）文件
CompletableFuture<String> readAsynchronously(Path file) {
    CompletableFuture<String> result = new CompletableFuture<>();
    try {
        AsynchronousFileChannel channel = AsynchronousFileChannel.open(file, StandardOpenOption.READ);
        ByteBuffer buffer = ByteBuffer.allocate((int) channel.size());
        // 读取已启动；回调对象将完成 CompletableFuture
        channel.read(buffer, 0, buffer, new CompletionHandler<Integer, ByteBuffer>() {
            @Override
            public void completed(Integer nbBytes, ByteBuffer read) {
                result.complete(new String(read.array(), 0, nbBytes, StandardCharsets.UTF_8));
            }

            @Override
            public void failed(Throwable e, ByteBuffer read) {
                result.completeExceptionally(e);
            }
        });
        // 读取结束时通道将被关闭，无论结果如何
        result.whenComplete((text, e) -> close(channel));
    } catch (IOException e) {
        result.completeExceptionally(e);
    }
    return result;
}

void processFiles() throws IOException {
    // 2 - 一次操作读取整个文件
    List<String> lines = Files.readAllLines(data);
    IO.println("2 - Files.readAllLines: " + lines.size() + " lines");

    // 3 - 用 BufferedReader 逐行读取
    List<TaxBracket> brackets = new ArrayList<>();
    try (BufferedReader reader = Files.newBufferedReader(data)) {
        String line;
        // 到达文件末尾时 readLine 返回 null
        while ((line = reader.readLine()) != null) {
            brackets.add(TaxBracket.parse(line));
        }
    }
    IO.println("3 - BufferedReader.readLine: " + brackets.size() + " brackets, 2nd: " + brackets.get(1));

    // 4 - Files.lines 返回按需读取的行 Stream
    try (Stream<String> stream = Files.lines(data)) {
        IO.println("4 - Files.lines: " + stream.count() + " lines");
    }

    // 5 - 用 BufferedWriter 写入
    try (BufferedWriter writer = Files.newBufferedWriter(report)) {
        writer.write("Brackets of the tax scale (exercise: 2004 tax scale on 2003 income)");
        writer.newLine();
        for (int i = 0; i < brackets.size(); i++) {
            TaxBracket bracket = brackets.get(i);
            String limit = bracket.limit().signum() == 0 ? "beyond"
                    : String.format("up to %,d €", bracket.limit().intValue());
            writer.write(String.format("bracket %d : %-18s rate %.1f %%",
                    i + 1, limit, bracket.coeffR().multiply(BigDecimal.valueOf(100))));
            writer.newLine();
        }
    }

    // 6 - 将整个文件读取为字符串
    String text = Files.readString(report);
    IO.print("5 and 6 - content of [" + report + "] :\n" + text);

    // 7 - 追加到文件末尾，然后删除它
    Files.writeString(report, "end of the report\n", StandardOpenOption.APPEND);
    IO.println("7 - last line: " + Files.readAllLines(report).getLast());
    Files.delete(report);
}

import com.sun.net.httpserver.HttpServer;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;

final int port = 27510;
final List<String> cities = List.of("Angers", "Brest", "Colmar", "Dijon", "Évry", "Foix");
long start;

void main() throws IOException, InterruptedException, ExecutionException {
    // 一个需要一秒钟才给出某城市“温度”的 HTTP 服务器
    HttpServer server = HttpServer.create(new InetSocketAddress(InetAddress.getLoopbackAddress(), port), 0);
    server.createContext("/temperature", exchange -> {
        // 请求的形式为 /temperature?city=xxx
        String parameter = exchange.getRequestURI().getRawQuery().substring("city=".length());
        String city = URLDecoder.decode(parameter, StandardCharsets.UTF_8);
        sleep(1000);
        byte[] response = (city + " : " + (10 + city.length()) + " °C").getBytes(StandardCharsets.UTF_8);
        exchange.sendResponseHeaders(200, response.length);
        try (OutputStream stream = exchange.getResponseBody()) {
            stream.write(response);
        }
    });
    // 每个收到的请求由一个虚拟线程处理
    server.setExecutor(Executors.newVirtualThreadPerTaskExecutor());
    server.start();

    try (HttpClient client = HttpClient.newBuilder().version(HttpClient.Version.HTTP_1_1).build()) {
        // 先发一个请求，让 JVM 在测量之前加载客户端类
        client.send(request("Paris"), HttpResponse.BodyHandlers.discarding());

        // 1 - sendAsync 立即返回 CompletableFuture<HttpResponse<String>>
        start = System.nanoTime();
        List<CompletableFuture<String>> responses = cities.stream()
                .map(city -> client.sendAsync(request(city), HttpResponse.BodyHandlers.ofString())
                        .thenApply(HttpResponse::body))
                .toList();
        CompletableFuture.allOf(responses.toArray(CompletableFuture[]::new)).join();
        display("1 - sendAsync: " + responses.stream().map(CompletableFuture::resultNow).toList());

        // 2 - send 是阻塞的：我们从虚拟线程调用它
        start = System.nanoTime();
        try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
            List<Future<String>> responses2 = new ArrayList<>();
            for (String city : cities) {
                responses2.add(executor.submit(
                        () -> client.send(request(city), HttpResponse.BodyHandlers.ofString()).body()));
            }
            List<String> texts = new ArrayList<>();
            for (Future<String> response : responses2) {
                texts.add(response.get());
            }
            display("2 - send on virtual threads: " + texts);
        }
    } finally {
        server.stop(0);
    }
}

    9.9. 异步值流

    异步操作在一段时间之后返回一个结果。流（[Stream]）或迭代器则按需返回一个序列的值。有时需要把两者结合起来：一个值序列，其中每个值在产生之前都需要等待。文件中的大量行、SQL 查询结果中的行、通过网络连接到达的消息、传感器读数……都属于这种情况。其他语言为此提供了专用类型；Java 提供两种模型：

    • “拉取”模型：消费者请求下一个值并等待其可用。使用虚拟线程时，这就是一个由虚拟线程读取的、每个值的产生都会阻塞的 [Iterator] 或 [Stream]；
    • “推送”模型：生产者在值产生时把它们发送给订阅者，由订阅者控制吞吐量。这就是响应式流模型，由 [java.util.concurrent.Flow] 接口（Java 9）标准化。

Stream<Measurement> readMeasurements(String sensor, int count) {
    return IntStream.rangeClosed(1, count)
            .mapToObj(i -> {
                // 等待下一次测量
                sleep(200);
                return new Measurement(sensor, i, 19.5 + i * 0.75);
            })
            // 由 close() 执行：正常结束时、break 之后或取消时
            .onClose(() -> IO.println("          " + sensor + " : end of production"));

// 等待线程结束 [timeout] 毫秒，然后中断它并等待其结束
void waitForEnd(Thread thread, long timeout) {
    try {
        thread.join(timeout);
        thread.interrupt();
        thread.join();
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
}

    9.9.2. 推送模型：Flow 和 SubmissionPublisher

    [java.util.concurrent.Flow] 接口（Java 9）把四个内部接口组合在一起，使响应式流标准化：

    • [Flow.Publisher<T>]，发布者，产生值；通过其方法 [subscribe] 向它添加订阅者；
    • [Flow.Subscriber<T>]，订阅者，通过其方法 [onNext] 接收值，通过 [onComplete] 接收流的结束，通过 [onError] 接收错误，并在开始时通过 [Flow.Subscription] 对象，经由 [onSubscribe] 与发布者相连；
    • [Flow.Subscription]，订阅：[request(n)] 请求来自 [n] 的额外值，而 [cancel()] 终止订阅。发布者发送的值绝不会超过订阅者所请求的数量：这就是“背压”（backpressure），它能防止快速的发布者压垮缓慢的订阅者；
    • [Flow.Processor<T, R>] 既是订阅者又是发布者（一个转换节点）。

    Java 提供了发布者的一个实现 [SubmissionPublisher<T>]，它通过执行器和每个订阅者专属的缓冲区向各个订阅者交付值。响应式库（Project Reactor、RxJava）实现了这些相同的接口，并为其添加了数十种运算符。程序 [Async20.java] 向两个订阅者发布六个测量值：一个快速的显示器，在温度超过 22 °C 时取消订阅；以及一个缓慢的归档器：

// 一个订阅者，处理每次测量耗时 [duration] 毫秒，并在超过 [threshold] 后取消订阅
class Subscriber implements Flow.Subscriber<Measurement> {
    private final String name;
    private final long duration;
    private final double threshold;
    private Flow.Subscription subscription;
    final CountDownLatch end = new CountDownLatch(1);

    Subscriber(String name, long duration, double threshold) {
        this.name = name;
        this.duration = duration;
        this.threshold = threshold;
    }

    @Override
    public void onSubscribe(Flow.Subscription subscription) {
        this.subscription = subscription;
        // 订阅者逐个请求值：由它来控制速率
        subscription.request(1);
    }

    @Override
    public void onNext(Measurement measurement) {
        display("  " + name + " : received " + measurement);
        sleep(duration);
        if (measurement.value() >= threshold) {
            display("  " + name + " : threshold reached, unsubscribing");
            subscription.cancel();
        } else {
            subscription.request(1);
        }
    }

    @Override
    public void onError(Throwable e) {
        display("  " + name + " : error " + e);
        end.countDown();
    }

    @Override
    public void onComplete() {
        display("  " + name + " : end of the stream");
        end.countDown();
    }
}

class RateService {

    private final AtomicInteger nbReadings = new AtomicInteger();

// 将温度计的通知转换为 CompletableFuture
CompletableFuture<Double> waitForTemperature(Thermometer thermometer, double threshold) {
    // 一个由我们自己来完成的 CompletableFuture
    CompletableFuture<Double> result = new CompletableFuture<>();
    // 达到阈值时，监听器完成该 CompletableFuture
    DoubleConsumer listener = temperature -> {
        if (temperature >= threshold) {
            result.complete(temperature);
        }
    };
    thermometer.addListener(listener);
    // 无论以何种方式结束（阈值、超时、取消），我们都移除监听器
    result.whenComplete((temperature, e) -> thermometer.removeListener(listener));
    // CompletableFuture 立即返回；它将在稍后完成
    return result;
}

final AtomicInteger inProgress = new AtomicInteger();

long start;

void main() {
    start = System.nanoTime();
    List<String> pages = IntStream.rangeClosed(1, 9).mapToObj(i -> "page" + i + ".html").toList();
    // 同一时间最多 3 个下载：一个有 3 个许可的信号量

    try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
        // 每个页面一个虚拟线程：它们开销很小，页面有多少就可以创建多少

                    permits.release();
                }
                return null;

// 生产者：每 50 毫秒一个订单
Void produce(int nbOrders) throws InterruptedException {
    for (int i = 1; i <= nbOrders; i++) {
        Thread.sleep(50);
        // 如果队列中有空位，offer 立即放入订单
        if (queue.offer(i)) {
            display("P  : order " + i + " queued");
        } else {
            // 队列已满：put 等待有空位腾出
            display("P  : queue full, order " + i + " waits");
            queue.put(i);
            display("P  : order " + i + " queued");
        }
    }
    // 不会再有产出：我们放入结束标记
    queue.put(END);
    display("P  : end of production");
    return null;
}

// 消费者：处理一个订单需要 400 毫秒
Void consume(String name) throws InterruptedException {
    while (true) {
        // take 等待直到队列中有订单
        int order = queue.take();

            // 我们把结束标记放回队列，供另一个消费者使用
            queue.put(END);
            break;
        }
        display(name + " : processing of order " + order);
        Thread.sleep(400);
    }
    display(name + " : no more orders");
    return null;
}

void main() throws InterruptedException {
    // 1 - 每 500 毫秒一个动作，2.2 秒后停止
    long start = System.nanoTime();
    AtomicInteger nbTicks = new AtomicInteger();
    try (ScheduledExecutorService scheduler = Executors.newSingleThreadScheduledExecutor()) {
        // scheduleAtFixedRate：500 毫秒后第一次触发，然后每 500 毫秒触发一次
        ScheduledFuture<?> ticks = scheduler.scheduleAtFixedRate(
                () -> IO.println(String.format("%6d ms : tick no. %d",
                        (System.nanoTime() - start) / 1_000_000, nbTicks.incrementAndGet())),
                500, 500, TimeUnit.MILLISECONDS);
        // schedule：一个单次动作，在 2.2 秒后停止触发
        ScheduledFuture<?> stop = scheduler.schedule(
                () -> ticks.cancel(false), 2200, TimeUnit.MILLISECONDS);
        stop.get();
        IO.println(String.format("%6d ms : timer stopped after %d ticks",
                (System.nanoTime() - start) / 1_000_000, nbTicks.get()));
    } catch (ExecutionException e) {
        IO.println("error: " + e.getCause());
    }

    // 2 - Clock：依赖时间的类接收其时钟，而不是调用 LocalDateTime.now()
    Clock morning = Clock.fixed(Instant.parse("2026-10-03T09:30:00Z"), ZoneOffset.UTC);
    Clock evening = Clock.fixed(Instant.parse("2026-10-03T19:45:00Z"), ZoneOffset.UTC);
    IO.println(new Reception(morning).greet("Pierre"));
    IO.println(new Reception(evening).greet("Pierre"));
    IO.println(new Reception(Clock.systemDefaultZone()).greet("Pierre") + " (system clock)");
}

    9.13. 结构化并发（概述）

    在前面的示例中，程序启动的操作独立于它运行：如果其中一个失败，其他的会继续；如果启动它们的代码被中断，它们同样会继续；而且没有任何机制强制该代码等待它们结束。结构化并发提议把一组子任务视为单个块：它们在一个作用域内启动，作用域等待它们完成，如果其中一个失败，其他的就会被取消。[StructuredTaskScope] 类使用虚拟线程实现了这一思想。它自 Java 21 起就已提供，但在 Java 25 中仍处于“预览”状态：其 API 仍可能改变，使用它的程序必须带 [--enable-preview] 选项编译和运行。因此它不包含在课程练习中；下面的代码（文件 [preview/StructuredConcurrency.txt]，要测试它，需将其复制到名为 [StructuredConcurrency.java] 的文件中）可以让你大致了解它的工作方式：

import java.util.concurrent.StructuredTaskScope.Joiner;
import java.util.concurrent.StructuredTaskScope.Subtask;

void main() throws InterruptedException {
    // 1 - 两个必须都成功的子任务
    try (var scope = StructuredTaskScope.open()) {
        Subtask<Integer> angers = scope.fork(() -> readTemperature("Angers", 1000));
        Subtask<Integer> brest = scope.fork(() -> readTemperature("Brest", 500));
        // join 等待子任务结束；如果其中一个失败，另一个被取消
        // 并且 join 抛出异常
        scope.join();
        IO.println("Angers: " + angers.get() + ", Brest: " + brest.get());
    }
    // 2 - 第一个回答就够了：其他子任务被取消
    try (var scope = StructuredTaskScope.open(Joiner.<Integer>anySuccessfulResultOrThrow())) {
        scope.fork(() -> readTemperature("mirror-paris", 800));
        scope.fork(() -> readTemperature("mirror-lyon", 300));
        IO.println("first answer: " + scope.join());
    }
}

        while (cause instanceof ExecutionException) {
            cause = cause.getCause();
        }
        IO.println("error: " + cause.getClass().getSimpleName() + " : " + cause.getMessage());
    } catch (IOException | InterruptedException e) {
        IO.println("error: " + e.getClass().getSimpleName() + " : " + e.getMessage());

// 读取税率档（limit:coeffR:coeffN，小数点）
List<TaxBracket> loadBrackets(Path file) throws IOException {
    try (Stream<String> lines = Files.lines(file)) {
        return lines.filter(line -> !line.isBlank()).map(TaxBracket::parse).toList();
    }
}

// 计算每个纳税人的税款并写入结果
int calculateTaxes(List<TaxBracket> brackets, List<String> taxpayers, Path output) throws IOException {
    try (BufferedWriter writer = Files.newBufferedWriter(output)) {
        for (String line : taxpayers) {
            Matcher fields = TAXPAYER.matcher(line.trim());
            String result = fields.matches()
                    ? "tax = " + calculateTax(brackets, fields.group(1).equals("y"),
                            Integer.parseInt(fields.group(2)), Integer.parseInt(fields.group(3))) + " €"
                    : "incorrect line";
            writer.write(String.format("%-12s : %s", line, result));
            writer.newLine();
        }
    }
    return taxpayers.size();
}

// 税款计算（2003 年收入适用的 2004 年税率表，为练习而保留）
int calculateTax(List<TaxBracket> brackets, boolean married, int nbChildren, int salary) {
    BigDecimal shares = BigDecimal.valueOf(nbChildren).divide(BigDecimal.TWO)
            .add(BigDecimal.valueOf(married ? 2 : 1));
    if (nbChildren >= 3) {
        shares = shares.add(new BigDecimal("0.5"));
    }
    BigDecimal income = new BigDecimal("0.72").multiply(BigDecimal.valueOf(salary));
    BigDecimal quotient = income.divide(shares, MathContext.DECIMAL64);
    // 限额超过家庭系数的第一个税率档，否则取最后一个
    TaxBracket bracket = brackets.stream()
            .filter(t -> quotient.compareTo(t.limit()) <= 0)
            .findFirst()
            .orElse(brackets.getLast());
    return bracket.coeffR().multiply(income).subtract(bracket.coeffN().multiply(shares)).intValue();
}

        String[] fields = line.split(":");
        return new TaxBracket(new BigDecimal(fields[0]), new BigDecimal(fields[1]),
                new BigDecimal(fields[2]));
    }
}

    9.15. 黄金法则

    让我们总结一下 Java 中异步编程的规则：

    • 要等待，就不要阻塞系统线程：等待（I/O、超时或其他操作）要么在虚拟线程中进行，要么通过给 [CompletableFuture] 附加后续操作来进行；
    • 对于新代码，优先使用虚拟线程：编写阻塞的、顺序的、可读的代码（循环、[try / catch]、普通的局部变量），由 [Executors.newVirtualThreadPerTaskExecutor()] 执行；每个任务一个虚拟线程，绝不要使用虚拟线程池；
    • 使用 [CompletableFuture] 来组合操作，或者使用返回 [CompletableFuture] 的 API（[HttpClient.sendAsync]、响应式库）；此时我们选择后续操作的执行器（[xxxAsync(..., executor)]），并且绝不在共享池中执行阻塞操作；
    • 不要在后续操作[join()] 或 [get()] 中或 GUI 线程里使用 ：这些等待会阻塞执行它们的线程。它们应当放在主程序或虚拟线程中；
    • 虚拟线程用于等待，而不是计算：对于计算，请使用按处理器数量确定大小的平台线程池，或并行流；
    • 使用 [Semaphore] 来限制对稀缺资源的访问，而不是依靠线程池的大小；
    • 取消是协作式的：通过 [Future.cancel(true)] 取消任务，这会中断其线程；被中断的任务应优雅地终止；[InterruptedException] 绝不能被掩盖（要么传播它，要么重置中断标志）。并且请记住，[CompletableFuture.cancel] 不会中断任何东西；
    • 限制等待时间：[orTimeout]、[completeOnTimeout]、[get(timeout, unit)]；如果放弃等待，就自行终止该操作；
    • 先启动，再等待：要同时运行多个相互独立的操作，先把它们全部启动，然后再等待它们（[allOf]、[invokeAll]、执行器的 [close] 方法）；
    • 已启动的操作必须被等待或监控：被遗忘的操作会隐藏它的异常（用 [exceptionally]、[whenComplete] 来处理它们）；通过回溯 [CompletionException] 或 [ExecutionException]，我们寻找根本原因。
