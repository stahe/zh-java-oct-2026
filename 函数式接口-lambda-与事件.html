    7. 函数式接口、Lambda 与事件

    在许多程序中，我们需要向方法传递的不是数据，而是行为：排序标准、过滤条件，或者在某件事发生时要执行的处理。Java 用一个简单的概念来满足这一需求，本章全部内容都以它为基础：函数式接口，即只声明一个抽象方法的接口。实现这种接口的对象“携带”着一个函数，该函数可以存放在变量中、作为参数传递、作为方法的结果返回，并可随时执行。

    在 Java 8（2014 年）之前，对于想要表达的每一种行为，都必须编写一个类——通常是匿名类——这十分冗长。Java 8 引入了 lambda 表达式 和 方法引用，让您可以用一行代码写出这种行为。我们在第 5 章的流 API 中已经不加详述地用过它们：在 [persons.stream().filter(p -> p.age() >= 18)] 中，我们向 [filter] 方法传递了一个 lambda，即函数式接口的一个实例。本章将解释这种语法背后的原理。本章最后讲解 事件，Java 用“监听器”来处理事件：监听器是向发射器注册、以便获知其中所发生事情的对象——通常是 lambda。Java 图形用户界面（Swing、JavaFX）和 Web 框架都依赖这一机制：按钮点击或（HTTP）请求的到达，都会通知给已注册的监听器。本课程不涉及图形用户界面；所有示例都是控制台程序。

    本章的程序是位于 [07-lambdas] 文件夹中的紧凑源文件。它们使用 [java LambdasNN.java] 运行。请注意，紧凑源文件会自动导入整个 [java.base] 模块：来自 [java.util.function]、[java.util] 或 [java.util.concurrent] 包的接口无需任何 [import] 语句即可使用。

    7.1. 预定义的函数式接口

    7.1.1. 函数式接口的概念

    函数式接口 是恰好只有一个抽象方法的接口。它还可以拥有任意数量的 [default] 方法和 [static] 方法（见第 4 章）：它们不计入。这个唯一的抽象方法描述了函数的一种模型（也称为签名或形式）：其参数的类型和返回值的类型。于是，该接口类型的变量可以引用任何提供这种形式函数的对象，并通过调用该方法来执行它。

    最古老的例子是 [java.lang.Runnable] 接口，它自 Java 1.0 起就已存在，表示一个待执行的任务（我们将在第 8 章讲线程时再回到它）。它只有一个方法：[void run();]。它描述的函数：

    • 没有参数；
    • 不返回结果（[void]）。

    创建 [Runnable] 类型的对象有三种方式：

    • 编写一个实现该接口的类，具名或匿名均可。这是 Java 8 之前唯一的方式；
    • 编写一个 lambda 表达式：[Runnable task = () -> IO.println("task");]；
    • 编写一个指向已有且形式正确的方法的 方法引用 ：[Runnable task = Functions::display;]。

    在后两种情况下，编译器会自行创建实现该接口的对象：lambda 或被引用的方法成为方法 [run] 的方法体。随后通过调用接口方法来执行该函数：[task.run()]。与其他语言不同，Java 没有专门的调用语法：始终通过名称调用接口方法（[run]、[apply]、[test]……）。

    7.1.2. java.util.function 包中的接口

    在 Java 8 之前，每个库都定义自己的单方法接口（[Runnable]、[Comparator]、[ActionListener]……）。Java 8 引入了 [java.util.function] 包，它提供 43 个泛型函数式接口，几乎涵盖了所有需求。主要的接口如下：

    // Java 预定义的函数式接口

void main() {
    // 1 - Runnable：无参数，无结果：void run()
    Runnable task = new Runnable() {
        @Override
        public void run() {
            Functions.display();
        }
    };
    // 简写形式：方法引用
    task = Functions::display;
    // 执行：我们调用接口唯一的抽象方法
    task.run();

    // 2 - BiFunction<T, U, R>：两个参数，一个结果
    BiFunction<Integer, Integer, Integer> operation = Functions::add;
    IO.println("operation.apply(2, 3)=" + operation.apply(2, 3));
    // Supplier<T>：无参数，一个结果
    Supplier<String> greet = Functions::greet;
    IO.println("greet.get()=" + greet.get());
    // 基本类型版本：IntBinaryOperator，int applyAsInt(int, int)，无装箱
    IntBinaryOperator multiply = Functions::multiply;
    IO.println("multiply.applyAsInt(2, 3)=" + multiply.applyAsInt(2, 3));

    // 3 - Consumer<T>：一个参数，无结果
    Consumer<String> write = IO::println;
    write.accept("Consumer<String> executed IO.println");

    // 4 - Predicate<T>：一个参数，布尔结果
    Predicate<Integer> isEven = Functions::isEven;
    IO.println("isEven.test(8)=" + isEven.test(8));
    List<Integer> numbers = new ArrayList<>(List.of(3, 8, 1, 6, 5, 4));
    // Collection 的 removeIf 需要一个 Predicate
    boolean modified = numbers.removeIf(isEven);
    IO.println("even numbers removed: " + modified + ", remaining: " + numbers);

    // 5 - Comparator<T>：两个 T 参数，int 结果
    List<String> names = new ArrayList<>(List.of("Paul", "Mélanie", "Jo", "Sébastien"));
    names.sort(Functions::compareLengths);
    IO.println("sorted by length: " + names);

    // 6 - lambda 是对象：是实现该接口的生成类的实例
    IO.println("class: " + operation.getClass().getName());
    IO.println("interfaces: " + Arrays.toString(operation.getClass().getInterfaces()));
}

// （精简源文件的隐式类无法被命名）
class Functions {

    static void display() {
        IO.println("display() executed by Runnable.run()");
    }

    static int add(int n1, int n2) {
        return n1 + n2;
    }

    static int multiply(int n1, int n2) {
        return n1 * n2;
    }

    static String greet() {
        return "Hello";
    }

    static boolean isEven(int n) {
        return n % 2 == 0;
    }

    static int compareLengths(String s1, String s2) {
        return Integer.compare(s1.length(), s2.length());
    }
}

    7.2. 定义自己的函数式接口

    预定义的接口通常已经够用，但您也可以定义自己的接口。只需编写一个只有一个抽象方法的接口，例如：

    • [interface Operation { int calculate(int n1, int n2); }]

    这个接口表示一个接受两个整数并返回一个整数的函数。与 [IntBinaryOperator]* 相比，类型 *[Operation] 的名称描述了其用途，它的方法有一个描述性的名称（[calculate] 而不是 [applyAsInt]*），它的参数也有名称（[n1]、[n2]），开发工具会显示这些名称。它前面带有注解 [@FunctionalInterface]*：这不是必需的，但它会指示编译器验证该接口是函数式接口，并且记录了开发者的意图。

    类型为 [Operation] 的变量 [op] 一次只能引用 一个函数。与提供“多播委托”的其他语言不同，Java 没有提供把多个函数存放在一个变量中并通过一次调用执行它们的方式：需要时，会把函数放入一个 列表 并逐个执行。这正是我们处理事件监听器时要做的事。

    // 定义自己的函数式接口

void main() {
    // Operation 类型的变量接收静态方法 increase
    Operation op = Calculations::increase;
    // 我们执行该操作
    int n = op.calculate(4, 7);
    IO.println("n=" + n);

    // 创建 Calculations 类型的对象 c1
    var c1 = new Calculations();
    // 我们把对象 c1 的 add 方法存入 op
    op = c1::add;
    n = op.calculate(2, 3);
    IO.println("n=" + n);
    // 然后是 c1 的 subtract 方法
    op = c1::subtract;
    n = op.calculate(2, 3);
    IO.println("n=" + n);

    // 一个变量只引用一个函数：要执行多个函数，我们使用列表
    List<Operation> operations = new ArrayList<>();
    operations.add(c1::add);
    operations.add(c1::subtract);
    operations.add((n1, n2) -> n1 * n2);
    for (Operation operation : operations) {
        IO.println("-> " + operation.calculate(10, 4));
    }

    // 接口的 default 方法构建一个新操作
    Operation squaredSum = ((Operation) c1::add).then(x -> x * x);
    IO.println("squaredSum.calculate(1, 2)=" + squaredSum.calculate(1, 2));

    // Operation 和 IntBinaryOperator 形式相同，但是两种不同的类型
    IntBinaryOperator other = op::calculate;
    IO.println("other.applyAsInt(5, 1)=" + other.applyAsInt(5, 1));

    // 泛型函数式接口
    Transformation<String, Integer> length = String::length;
    Transformation<Integer, String> stars = "*"::repeat;
    IO.println("length(\"Hello\")=" + length.transform("Hello"));
    IO.println("stars(5)=" + stars.transform(5));
}

// 函数式接口的定义：只有一个抽象方法
// 接受两个整数作为参数并返回一个整数
@FunctionalInterface
interface Operation {
    int calculate(int n1, int n2);

    // default 方法不计入：该接口仍然是函数式接口
    default Operation then(IntUnaryOperator next) {
        return (n1, n2) -> next.applyAsInt(calculate(n1, n2));
    }
}

// 泛型函数式接口：T -> R
@FunctionalInterface
interface Transformation<T, R> {
    R transform(T value);
}

// 其方法具有 Operation 接口形式的类
class Calculations {
    // 两个实例方法
    int add(int n1, int n2) {
        IO.println("add(" + n1 + "," + n2 + ")");
        return n1 + n2;
    }

    int subtract(int n1, int n2) {
        IO.println("subtract(" + n1 + "," + n2 + ")");
        return n1 - n2;
    }

    // 一个静态方法
    static int increase(int n1, int n2) {
        IO.println("increase(" + n1 + "," + n2 + ")");
        return n1 + 2 * n2;
    }
}

    // 1 - 匿名类：实现接口的类就地编写
    IntBinaryOperator add = new IntBinaryOperator() {

        public int applyAsInt(int n1, int n2) {

void main() {
    // 1 - Function：andThen（先执行自身，再执行另一个）和 compose（先执行另一个）
    Function<Integer, Integer> plusOne = x -> x + 1;
    Function<Integer, Integer> timesTwo = x -> x * 2;
    IO.println("plusOne.andThen(timesTwo).apply(5)=" + plusOne.andThen(timesTwo).apply(5));
    IO.println("plusOne.compose(timesTwo).apply(5)=" + plusOne.compose(timesTwo).apply(5));

    List<UnaryOperator<String>> steps =
            List.of(String::strip, String::toLowerCase, s -> s.replace(' ', '-'));
    Function<String, String> normalize = Function.identity();
    for (UnaryOperator<String> step : steps) {
        normalize = normalize.andThen(step);
    }
    IO.println("normalize(\"  My Nice Title \")=" + normalize.apply("  My Nice Title "));

    // 2 - Predicate：and、or、negate、Predicate.not
    Predicate<String> isShort = s -> s.length() <= 4;
    Predicate<String> startsWithP = s -> s.startsWith("P");
    List<String> firstNames = List.of("Paul", "Mélanie", "Jo", "Sébastien", "Pierre");
    IO.println("short and P: " + filter(firstNames, isShort.and(startsWithP)));
    IO.println("short or P: " + filter(firstNames, isShort.or(startsWithP)));
    IO.println("not short: " + filter(firstNames, isShort.negate()));
    IO.println("not empty: " + filter(List.of("a", "", "b"), Predicate.not(String::isEmpty)));

    // 3 - Consumer：andThen 对同一个值串联两个处理
    List<String> log = new ArrayList<>();
    Consumer<String> display = s -> IO.println("display: " + s);
    Consumer<String> remember = log::add;
    Consumer<String> both = display.andThen(remember);
    both.accept("first");
    both.accept("second");
    IO.println("log: " + log);

    // 4 - Comparator：comparing、thenComparing、reversed
    List<Person> persons = new ArrayList<>(List.of(new Person("Paul", 32),
            new Person("Mélanie", 25), new Person("Jo", 32), new Person("Sébastien", 25)));
    persons.sort(Comparator.comparing(Person::age).thenComparing(Person::name));
    IO.println("by age then name: " + persons);
    persons.sort(Comparator.comparingInt(Person::age).reversed()
            .thenComparing(Person::name, Comparator.reverseOrder()));
    IO.println("by descending age then descending name: " + persons);
    // BinaryOperator.minBy 由比较器构建函数
    BinaryOperator<Person> youngest = BinaryOperator.minBy(Comparator.comparingInt(Person::age));
    IO.println("youngest(Paul, Mélanie)=" + youngest.apply(persons.get(0), persons.get(3)));
}

static <T> List<T> filter(List<T> elements, Predicate<? super T> predicate) {
    List<T> result = new ArrayList<>();
    for (T element : elements) {
        if (predicate.test(element)) {
            result.add(element);
        }
    }
    return result;
}

    7.5. 事件处理

    7.5.1. 监听器模型

    函数式接口用于建立事件机制。Java 没有专门用于事件的关键字：它使用一组约定，称为“监听器模型”，早在 Java 1.1 中就为图形组件和 JavaBeans 确立了。类 [C1] 想要发出事件 [Xxx] 时，按如下方式进行：

    • 一个 [XxxEvent] 类，派生自 [java.util.EventObject]，封装事件信息。[EventObject] 存储触发事件的对象——称为 源——可通过 [getSource()] 获得；
    • 一个接口 [XxxListener]，它扩展空接口 [java.util.EventListener] （一个简单的标记），定义事件发生时将被调用的方法。如果只有一个方法，它就是函数式接口：监听器可以是 lambda；
    • [C1] 类管理一个监听器列表，并提供两个公共方法用于订阅和取消订阅：[addXxxListener(XxxListener l)] 和 [removeXxxListener(XxxListener l)]；
    • 当 [c1] 实例（属于 [C1] ）想要发出事件时，它会创建一个 [XxxEvent] 对象，并调用每个已注册监听器的方法，把该对象传给它。按照约定，这种通知由一个受保护的方法 [fireXxx(XxxEvent e)] （“fire”，触发）负责处理，派生类可以重写它来修改事件的发布方式；
    • 如果 [c2] 对象想要获知 [Xxx] 事件，该事件来自 [c1] 对象，它就使用 [c1.addXxxListener(...)] 注册自己。当它不再希望收到通知时，可以通过 [c1.removeXxxListener(...)] 取消订阅。由于 [c1] 管理的是一个列表，不同的对象可以订阅以获知同一个事件。

    在这种情形中，我们有：

    • 一个发出（也称为“发布”或“发射”）事件的类；
    • 获知该事件的对象。它们被称为订阅或注册该事件：这些就是监听器，即事件处理程序；
    • 一个监听器接口，它定义将被通知该事件的方法的签名。

    这就是 观察者 设计模式：发射器并不了解它的订阅者；它只是通知它们。这种模型提供的保护与专用关键字相同：监听器列表是发射器的私有字段。从外部只能订阅或取消订阅；不能清空列表、替换其他监听器，也不能代替发射器触发事件。

// 发出事件信号的类
class Emitter {
    // 触发事件的阈值
    static final double THRESHOLD = 19;
    // 发射器的名称
    private final String name;
    // 观测到的温度
    private double temperature;
    // 已注册的监听器
    private final List<TemperatureTooHighListener> listeners = new CopyOnWriteArrayList<>();

    Emitter(String name) {
        this.name = name;
    }

    String getName() {
        return name;
    }

    double getTemperature() {
        return temperature;
    }

    void setTemperature(double temperature) {
        this.temperature = temperature;
        if (temperature > THRESHOLD) {
            // 我们向监听器发出事件信号
            fireTemperatureTooHigh(new TemperatureTooHighEvent(this, temperature));
        }
    }

    // 注册监听器
    void addTemperatureTooHighListener(TemperatureTooHighListener listener) {
        listeners.add(Objects.requireNonNull(listener));
    }

    // 注销监听器
    void removeTemperatureTooHighListener(TemperatureTooHighListener listener) {
        listeners.remove(listener);
    }

    // 向所有已注册的监听器通知事件
    protected void fireTemperatureTooHigh(TemperatureTooHighEvent e) {
        for (TemperatureTooHighListener listener : listeners) {
            listener.temperatureTooHigh(e);
        }
    }
}

    说明：

    • 第 1–28 行：类 [TemperatureTooHighEvent] 按照约定派生自 [EventObject]。它的构造函数（第 10–13 行）把事件源传给 [EventObject] 的构造函数（[super(source)]），并存储触发事件的温度。我们增加了事件时间 [time] （第 8 行）。字段是 [final] 的，并且该类只有只读的访问器：监听器不得修改事件信息，以免影响后续的监听器；
    • 第 3–4 行：[EventObject] 实现了 [Serializable] 接口（以便事件可以被记录或通过网络传输）。使用 [-Xlint:all] 选项时，编译器随后要求每个派生类声明一个版本号 [serialVersionUID]。[@Serial] 注解（Java 14）向编译器标明这个特定的字段；
    • 第 16–19 行：[getSource] 方法在 [EventObject] 中返回一个 [Object]。我们用更具体的返回类型 [Emitter] 重新定义它，Java 允许这样做（协变返回类型）：监听器无需对事件源进行强制转换。这里我们不能使用 *[record]* ：记录不能继承任何类，因此也就不能继承 *[EventObject]*；
    • 第 30–34 行：监听器接口。它扩展 [EventListener] 并声明了唯一的方法 [temperatureTooHigh]，该方法接收事件对象：这是一个函数式接口；
    • 第 39 行：温度阈值，超过它就触发 [TemperatureTooHigh] 事件；
    • 第 41 行：发射器有一个用于标识的名称；
    • 第 45 行：已注册监听器的列表。这是一个 [CopyOnWriteArrayList] ，来自 [java.util.concurrent] 包，这种列表每当被修改时，都会把内容复制到一个新数组中。因此，正在进行的迭代会在旧数组上继续，即使在此期间列表被修改。稍后我们会看到为什么这在这里至关重要。这种列表是监听器列表的标准类型：每个事件都要遍历列表，但很少修改它；
    • 第 59–65 行：方法 [setTemperature] 记录新的温度，如果它超过阈值就发出事件；
    • 第 63 行：发布由 [fireTemperatureTooHigh] 方法处理，向它传递一个 [TemperatureTooHighEvent] 对象；该对象来自发射器自身（[this]），并包含超过阈值的温度；
    • 第 68–70 行：注册监听器就是把它添加到列表中。[Objects.requireNonNull] 会立即拒绝 [null] 监听器，否则它会在很久以后的通知过程中触发 [NullPointerException] ；

class Subscriber {
    // 订阅者的名称
    private final String name;
    // 可接受的最大警报数
    private final int nbAlertsMax;
    // 已收到的警报数
    private int nbAlerts;

    private final TemperatureTooHighListener listener = this::evtTemperatureTooHigh;

    Subscriber(String name, int nbAlertsMax) {
        this.name = name;
        this.nbAlertsMax = nbAlertsMax;
    }

    // 向发射器注册
    void subscribe(Emitter emitter) {
        emitter.addTemperatureTooHighListener(listener);
    }

    // 注销
    void unsubscribe(Emitter emitter) {
        emitter.removeTemperatureTooHighListener(listener);
    }

    // TemperatureTooHigh 事件的处理程序
    private void evtTemperatureTooHigh(TemperatureTooHighEvent e) {
        Emitter emitter = e.getSource();
        IO.println("Subscriber [%s]: the source [%s] reported a temperature too high: [%.1f]"
                .formatted(name, emitter.getName(), e.getTemperature()));
        // 超过 nbAlertsMax 个警报后，订阅者取消订阅
        nbAlerts++;
        if (nbAlerts == nbAlertsMax) {
            unsubscribe(emitter);
            IO.println("Subscriber [%s]: unsubscribed after %d alert(s)".formatted(name, nbAlerts));
        }
    }
}

class Tools {
    // 用谓词过滤列表：filter 所做的工作
    static <T> List<T> filter(List<T> source, Predicate<? super T> predicate) {
        List<T> result = new ArrayList<>();
        for (T element : source) {
            if (predicate.test(element)) {
                result.add(element);
            }
        }
        return result;
    }

    static boolean isOdd(int n) {
        return n % 2 != 0;
    }

    // 一个中间流操作，只放行满足谓词的元素
    static <T> Gatherer<T, ?, T> filter(Predicate<? super T> predicate) {
        return Gatherer.of((_, element, downstream) -> !predicate.test(element) || downstream.push(element));
    }

    // 一个转换每个元素的中间操作：相当于 map
    static <T, R> Gatherer<T, ?, R> transform(Function<? super T, ? extends R> transformation) {
        return Gatherer.of((_, element, downstream) -> downstream.push(transformation.apply(element)));
    }
}

    7.7. 表达式树

    一些语言（如 C#）允许把 lambda 转换为数据结构而不是可执行代码，该数据结构描述了这个 lambda（即“表达式树”）：这样程序就可以解析 lambda [t -> t.getLimit() > 20000] ，并把它翻译成，例如，由数据库服务器执行的 SQL 子句 [WHERE limits > 20000] 。

    Java 没有等价的机制。Java 的 lambda 总是被编译成可执行代码：您可以调用它，但无法检查它做了什么。因此，数据库访问库使用其他方式来表达查询。我们将在第 11 章介绍的 Hibernate 提供了两种解决方案：一种是类似于 SQL 但以类和属性来表达的查询语言，HQL （["from Bracket t where t.limit > 20000"]），以及 Jakarta Persistence 的 Criteria API，它通过方法调用来构造查询（[cb.gt(t.get("limit"), 20000)]）。在这两种情况下，查询都是数据（字符串或对象树），由 Hibernate 把它翻译成 SQL，而传给 [filter] 的 lambda 则是在 Java 程序内部执行的。

    7.8. 结论

    本章的要点：

    • 函数式接口是只有一个抽象方法的接口。[java.util.function] 包中的预定义接口（[Function]、[Supplier]、[Consumer]、[Predicate]、它们的双参数变体及其基本类型版本），以及 [Runnable]、[Callable] 和 [Comparator]，通常使您无需定义自己的接口；如果定义了，就用 [@FunctionalInterface] 注解它；
    • 函数式接口可以由类（具名或匿名）、lambda 表达式或方法引用（[Class::staticMethod]、[object::method]、[Class::instanceMethod]、[Class::new]）来实现。lambda 本身没有类型：由目标类型决定它的类型；
    • lambda 会捕获其周围的局部变量，前提是这些变量实际上是 final 的；可变状态通过对象或字段来处理；
    • 方法 [andThen]、[compose]、[and]、[negate]、[comparing]、[thenComparing]……可以根据现有函数构建新函数；
    • 在 Java 中，lambda 是接口的一个实例：函数式接口用于简短的一次性行为，而具有多个方法的接口（或“业务”接口）则用于应用程序的角色；
    • 事件通过监听器模式建立：一个 [XxxEvent] 类，派生自 [EventObject]；一个接口 [XxxListener]；方法 [addXxxListener] / [removeXxxListener], ；以及一个监听器列表（[CopyOnWriteArrayList]），由方法 [fireXxx] 迭代它。要取消订阅某个监听器，必须保留已订阅的对象。[PropertyChangeSupport] 为属性变更提供了开箱即用的这种机制；
    • 流 API 建立在接受函数式接口的操作之上；Java 没有表达式树，Hibernate 用 HQL 或 Criteria API 来表达它的查询。

    lambda 将在后续所有章节中再次出现：线程执行一个 [Runnable], 而 [ExecutorService] 执行 一个 [Callable] （第 8 章），[CompletableFuture] 把函数串联起来（第 9 章），Spring Boot Web 服务在框架作为监听器调用的方法中处理 HTTP 请求（第 13 章）。
